# 期货多周期回测报告 Skill 设计

## 目标

新增仓库级 `futures-multicycle-backtest-report` Skill，把正式版对比实验的多周期报告格式固定下来。以后用户要求“多周期回测、与正式版比较、画资金曲线”时，统一输出全周期、1年、2年、3年结果，并确保每个滚动周期同时包含1月和6月独立起点。

## 范围

- 只新增一个说明型 `skills/futures-multicycle-backtest-report/SKILL.md`。
- 不新增绘图器、校验脚本、回测引擎或策略参数。
- 不修改正式策略、正式配置、正式物料、生产目录、CTP或订单链路。
- 与策略版本晋级有关时，要求先使用 `version-ab-experiment`；本 Skill只规定多周期取样、图表和报告合同。

## 固定合同

### 窗口

- 必须包含一次正式版与候选版的完整周期独立回测。
- 固定滚动周期为1年、2年、3年。
- 每个周期必须枚举数据范围内所有能够完整结束的1月1日和6月1日起点。
- 每个周期至少要有一个完整1月起点和一个完整6月起点；数据不足时报告失败并说明覆盖不足，不得静默省略6月起点。
- 数据末端距离自然终点很近的窗口可以标记为 `near-complete`，只能展示，不能参与决策统计。
- 每个窗口必须独立冷启动回测引擎；禁止从全周期资金曲线事后裁切窗口指标。

### 比较与指标

- A固定表示当时可验证的正式基线；候选臂使用B/C等明确标识。
- 运行前冻结数据截止日、起点规则、候选臂、成本口径和晋级门，并记录冻结提交。
- 每个窗口至少记录期末权益、总收益、最大回撤、Sharpe、总滑点、总交易次数、胜率、账户生存和适用的保证金门。
- 分别汇总每个周期的全部窗口、1月起点和6月起点；不得只报告合并结果。

### 固定图表

按以下顺序输出并在最终回复中直接展示：

1. 完整周期正式版与候选版资金曲线。
2. 1年独立滚动资金曲线网格。
3. 2年独立滚动资金曲线网格。
4. 3年独立滚动资金曲线网格。
5. 多周期汇总图。

1/2/3年网格按年份排序，同一年1月起点在前、6月起点在后。标题必须显示准确起始日期和周期；观察窗口使用 `*` 标记并解释。正式版保持同一种颜色，候选版保持另一种颜色，坐标单位和图例在所有图中一致。

### 固定中文报告

报告先给晋级结论，再给：

- 正式基线与候选臂身份。
- 完整周期指标对比。
- 1/2/3年汇总表。
- 每个周期的1月与6月起点拆分结果。
- 最差收益、最大回撤恶化、Sharpe恶化和成本压力窗口。
- 五张资金曲线图及CSV、decision和阶段记录链接。
- 独立reviewer结论、测试证据、安全边界。
- 运行前后过拟合判断与继续价值判断。

完整周期或单一周期的优势不得覆盖其他周期、1月起点或6月起点的失败。

## Skill触发

以下请求触发：多周期回测、多起点稳健性、1年/2年/3年资金曲线、半年起点、与正式版比较、正式晋级前周期审计。

纯单窗口回测、仅归因分析、仅查看既有一张曲线时不自动触发。

## 验证

- 用无Skill的基线场景确认普通执行容易只给逐年1月起点或从完整曲线切片。
- 加载Skill后用同一场景验证其明确要求全周期、1/2/3年、每个周期完整覆盖1月和6月独立冷启动，并按固定顺序给出五张图和中文报告。
- 使用 Skill validator 检查frontmatter、名称和占位符。
- 独立reviewer检查描述是否可发现、合同是否无歧义、是否错误扩大实盘或master权限。

## 集成

在独立分支完成并验证后，不创建PR，直接以非force fast-forward方式推送到 `origin/master`；推送前后读取远端master SHA，确保只有设计文档和Skill进入本次提交。
