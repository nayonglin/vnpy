# 天勤旧合约日线失败原因：权限与合约解析分开判定

核查时间：2026-10-17 17:40—17:41 CST；解释记录：17:46 CST。运行环境为本机研究 `.py311`，TqSdk 3.10.2。仅访问行情服务，使用 TqSim；没有连接 CTP、券商账户或调用订单接口。

## 已确认的事实

三条路径分别创建独立 API 会话，使用已有本机配置；登录均成功取得 access token。服务返回的原始权限列表中 `futr=true`、`tq_dl=false`。仅记录权限布尔值，凭证、账号标识和 token 不进入证据文件。

| 路径 | 参数 | 实际失败位置与原因 | 证据 |
| --- | --- | --- | --- |
| `get_kline_data_series` | `SHFE.rb1505`，86400秒，2014-01-01至2015-06-01 | SDK `_get_data_series` 首先检查 `tq_dl`，报“get_kline_data_series 数据获取方式仅限专业版用户使用”；尚未下载具体合约历史 | `range.json` |
| `get_kline_serial` | 同合约，86400秒，1000根 | 服务端合约查询返回 `contains non-existent instrument: SHFE.rb1505` | `serial.json` |
| `TqBacktest` 时间快照 + `get_kline_serial` | 同合约、日线，快照起点2015-04-29，持续21天 | 同一服务端合约解析错误；把时间移回历史没有绕过此错误 | `snapshot.json` |

官方文档明确将区间接口标为专业版功能：[TqApi.get_kline_data_series](https://doc.shinnytech.com/tqsdk/latest/reference/tqsdk.api.html#tqsdk.TqApi.get_kline_data_series)。本机 SDK `api.py` 的权限检查和实际错误一致。普通序列接口必须按其自身错误单独解释，不能把专业版限制套到全部天勤接口。

## 判断与边界

1. 已有账号可正常认证，具有期货行情权限；不是密码错误，也不是周末休市导致这两类失败。
2. 现有身份缺少所需区间下载权限；普通序列及历史快照路径又无法解析本次测试的 `rb1505`。这两个事实足以解释本次未能用现有天勤身份补齐老合约日线。
3. `non-existent instrument` 是当前服务对该代码的返回，不代表交易所当年没有这张合约，也不能外推为所有退市合约都无法访问。上期所官方档案确实含有它。
4. 未测试其他套餐或授权身份，不能承诺购买专业版就一定解决全部2014—2019合约覆盖；本轮未购买、申请试用或修改套餐。
5. 此前只保留通用 Exception/超时的探针不能支持以上精确归因；本次按用户要求补充一次有界、脱敏诊断后，已有明确错误，不再反复重试。
