## Stage001 研究假设

上一条 `futures_trend_signed_covariance_risk_budget` 失败，是因为它实际只有 40 个收益观测，并把整个组合的绝对 inflation 施加给新候选，不是候选自身的边际风险贡献。Stage001 重新定义为：

- 使用回测引擎真实日线 `history_data`，按交易日期 inner join，对每个候选严格取截至信号日的 `63` 个共同收益观测。
- 候选和当前持仓均按方向调整收益：long 为 `+return`，short 为 `-return`。
- 使用 Ledoit-Wolf 收缩协方差。
- 风险暴露使用当前手数 × 合约乘数 × 最后共同收盘价。
- 先运行正式 C9 的 AI、相关性、selection tilt、并发和增量保证金规则，再在最终候选手数上计算边际风险。
- 按实际执行顺序把当天此前已接受的候选加入临时组合，使同日批量开仓彼此可见。
- 当前组合方差为 `V0`，候选满手加入后的增量方差为 `2*cross + standalone`。
- 当 `cross <= 0` 时候选提供分散化，不缩手、不加杠杆。
- 当 `cross > 0` 时，只消除正协方差造成的额外风险；解析求解 `standalone*a^2 + 2*cross*a = standalone`，并把 `a` 限制在 `(0,1]`。
- 整数手按最近整数收缩，原本可开的候选至少保留 `1` 手。
- 不减已有趋势仓，不改退出、止损、0.5R 当日止损重试、换月或加仓逻辑。

## Stage001 硬门槛

- C 总收益必须为正，且收益保留率 `>= 70%`。
- C 全周期最大回撤相对 A 改善至少 `3` 个百分点。
- C 2022 年内局部最大回撤相对 A 改善至少 `5` 个百分点。
- C 固定主压力窗 `2022-07-15 -> 2024-05-10` 最大回撤改善至少 `3` 个百分点。
- C broker10 峰值不得恶化。
- 所有 available 协方差样本必须严格为 `63` 个按日期对齐的收益观测，未来日期违规为 `0`。
- 候选规则最终手数不得高于正式规则最终手数，不得把原本正手数归零；`cross <= 0` 的分散化候选不得被缩手。
- 对“有当前持仓或同日已接受候选”的 opened 样本，协方差覆盖率至少 `80%`。
- 独立 agent review 必须确认绩效、AI、日期、数学、手数、路径和统计口径。

## 外部调研判断

- 风险预算文献用 Euler 分解定义边际风险贡献，核心是候选与现有组合的协方差，而不是整个组合的绝对 inflation。
- Ledoit-Wolf 可缓解小样本协方差矩阵病态，但不能替代日期对齐、真实交易路径和整数手约束。
- `pysystemtrade` 将相关矩阵、波动缩放和组合构建分层；本线只借鉴风险贡献结构，不复制加杠杆或动态优化。
- 我的判断：该结构具有跨周期的一般性，且直接修复上一线的两个 P1；但 C9 已有有效 pairwise correlation gate，增量价值不确定，必须以真引擎为裁决。
